# Байкал-центр — запуск и развёртывание

## Что входит
- Flask-приложение (`app.py`) и HTML-шаблоны;
- изображения и PDF из переданного архива;
- Dockerfile и конфигурация Amvera (`amvera.yaml`);
- пример переменных окружения (`.env.example`).

Локальная база `instance/baikal.db` намеренно не включена: в ней могут находиться пользовательские данные и бронирования. На Amvera используйте подключённую PostgreSQL.

## Важное про постоянное хранилище
В Amvera конфигурация монтирует постоянное хранилище в `/data`. Приложение должно хранить загружаемые фотографии и документы в `/data/uploads`. Не создавайте для этого папку `data` внутри репозитория: это другая директория и она не является постоянным хранилищем.

В текущем исправлении загрузка, выдача и удаление PDF используют один каталог `UPLOAD_FOLDER/documents`. Старые URL документов в базе поддерживаются по имени файла.

## Переменные окружения
Скопируйте значения из `.env.example` в настройки приложения Amvera:
- `AMVERA=1`
- `SECRET_KEY` — длинный случайный секрет Flask;
- `ADMIN_SECRET_KEY` — отдельный длинный случайный секрет входа в админ-панель;
- `ADMIN_PASSWORD` — новый пароль администратора;
- `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DB_NAME` — параметры PostgreSQL.

Не отправляйте `.env`, пароли, секреты или рабочую базу данных в GitHub и ZIP-архивы.

## Развёртывание
1. Сделайте резервную копию PostgreSQL и содержимого постоянного хранилища Amvera.
2. Проверьте, что в переменных Amvera заданы все значения из раздела выше.
3. Отправьте содержимое проекта в подключённый Git-репозиторий.
4. Запустите сборку и проверьте логи.
5. После запуска проверьте главную страницу, вход в личный кабинет, админ-панель, создание тестовой брони, загрузку/открытие/удаление тестового PDF и загрузку фотографии.
6. Не очищайте `/data/uploads`: там могут находиться 25 фотографий номеров, на которые ссылается локальная копия базы, но которых нет в присланном архиве.

## Ограничения проверки
Исходный код проверен на синтаксический уровень. В текущей среде отсутствуют Flask и часть зависимостей, а доступа к вашей PostgreSQL и контейнеру Amvera нет, поэтому полноценный интеграционный тест и проверка после реального развёртывания здесь не выполнялись. Не заменяйте рабочую БД локальной копией из архива.


## Временное отключение онлайн-бронирования

На Amvera онлайн-бронирование выключено по умолчанию: кнопка бронирования, формы, ссылки на вход/регистрацию и раздел бронирований в админ-панели не отображаются. Маршруты бронирования временно отвечают 404. Код, таблицы и существующие записи в базе данных не удаляются.

Чтобы включить бронирование обратно, добавьте в переменные окружения Amvera `ENABLE_BOOKING=true` и перезапустите приложение. Локально бронирование включено по умолчанию; для локального отключения задайте `ENABLE_BOOKING=false`.
